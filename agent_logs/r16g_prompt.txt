## Deliverable A — `web/src/app/api/chat/route.ts`: flavor support

Add env `HERMES_BACKEND_FLAVOR` (`gateway` default = exact current behavior / `hermes_api` = transform below). In `hermes_api` mode the proxy must re-emit the upstream stream in the EXISTING client contract:

1. Parse upstream SSE robustly (chunk boundaries; handle `event:`-named frames and plain `data:` frames; skip unknown events; tolerate keep-alives).
2. `hermes.tool.progress` status=running → emit `data: {"type":"tool","id":<toolCallId>,"name":<normalized>,"state":"running"}`. Normalize the tool name: strip a leading `mcp__hermes_search__` (map `mcp__hermes_search__hermes_places` → `hermes_places`); leave other names as-is. Include `args` only if reliably known (else omit — do not invent).
3. `hermes.tool.progress` status=completed → do NOT emit yet: register a pending result fetch (Deliverable B); emit `data: {"type":"tool","id":…,"name":…,"state":"done","result":<parsed payload or null>}` as soon as the fetch settles (or null on bounded timeout).
4. `hermes.status` → emit `data: {"type":"status","label":<text>}`.
5. OpenAI chunks → re-frame and passthrough as-is (keep `choices[].delta.content` semantics; keep `reasoning_content` deltas — harmless).
6. On upstream `data: [DONE]`: wait for pending result fetches to settle (hard bound ≈3s total), emit any remaining `done` frames, then emit `data: [DONE]` and close. Order guarantee: every `done` frame for a tool MUST precede `[DONE]`.
7. Sessions: read `threadId` from the request body (Deliverable C); when present, forward `X-Hermes-Session-Id: web-<threadId>` upstream. Capture the upstream response header `X-Hermes-Session-Id` and forward it on the browser response (debug aid).
8. Keep the existing error behavior for unreachable/other-than-2xx upstream (`sseError` with detail). 401 must surface a clear message.
9. Keep `gateway` mode byte-identical to today (pure passthrough).

## Deliverable B — tool result fetch (in `hermes_api` mode)

When a tool completes: `GET {backend_origin}/api/sessions/web-<threadId>/messages` with the same Bearer key (`backend_origin` derived from `HERMES_BACKEND_URL`), find the LATEST message with `role=="tool"` and `tool_call_id==<toolCallId>`, JSON-parse its `content` (it may be a JSON string; be defensive — `JSON.parse`, else try to locate an embedded JSON object, else null). Transcript writes can lag the stream: retry ≈3× every ~300-400ms; if still absent → `result: null` (never throw into the stream). No threadId → skip fetch, `result: null`. At most one fetch chain per completed tool.
