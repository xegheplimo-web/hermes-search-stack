  ```python
  ukey, sha = url_key(url), content_sha256(text)
  same = store.conn.execute("SELECT 1 FROM documents WHERE url_key=? AND content_sha256=?", (ukey, sha)).fetchone()
  if same:
      counts["unchanged"] += 1
  elif store.conn.execute("SELECT 1 FROM documents WHERE url_key=? LIMIT 1", (ukey,)).fetchone():
      counts["updated"] += 1
  else:
      counts["new"] += 1
  store.ingest_document(url, text, title=..., provider=..., format=..., meta=...)
  ```

## §3 `refresh.py` (R5-A) — coverage + auto-backfill

Purpose: (a) report which VN data is present/missing per area per source, (b) fetch the missing/stale data with dedup guarantees (re-running an unchanged refresh adds nothing).

- `load_config(path) -> dict` — JSON:
  ```json
  {
    "areas": [
      {"name": "Yên Dũng", "province": "Tỉnh Bắc Ninh",
       "overpass": {"bbox": [21.17, 106.20, 21.24, 106.30], "categories": ["food", "shops"]},
       "ckan": {"datasets": ["haiphong-new"]}}
    ]
  }
  ```
  Validate: `areas` non-empty; each has non-empty `name`; optional `province` (str); optional `overpass` = `{bbox: [s,w,n,e] 4 numbers, categories: non-empty list ⊆ CATEGORIES}`; optional `ckan` = `{datasets: non-empty list ⊆ known enterprise dataset keys}`. Invalid → `VnGeoError` naming the offending area/key.
- `coverage(store, *, config=None, area=None) -> dict` — NO network, pure store reads:
  ```json
  {"checked_at": "<iso8601>", "areas": [
    {"name": "Yên Dũng",
     "sources": {
       "admin":    {"count": 99, "present": true, "latest_fetched_at": "<iso|null>"},
       "overpass": {"count": 0,  "present": false, "latest_fetched_at": null},
       "ckan":     {"count": 1429, "present": true, "latest_fetched_at": "..."},
       "places":   {"count": 7,  "present": true, "latest_fetched_at": "..."}},
     "gaps": ["overpass"]}
  ]}
  ```
  Counting rules (documented approximations — use SQL on `documents_current`):
  - admin: provider `provinces-api`, `meta LIKE '%<province-or-name>%'`.
  - ckan: providers `ckan-<province>` of the area's configured datasets (dedupe providers).
  - overpass: if bbox configured → Python-filter `provider='osm'` docs whose meta lat/lon fall inside bbox; else all `osm` docs with a `"scope": "global"` note in that source dict.
  - places: providers in `places.PLACE_SOURCES` (except osm already counted — keep it simple: count all four, document overlap), `meta LIKE '%<area name>%'`.
  - `latest_fetched_at` = `MAX(fetched_at)` for the same filter. `gaps` = sources with `present=false`.
  - Areas: `area` arg → that single name (no config needed, filters by name only); else `config["areas"]`; else `[]`.
- `refresh(store, *, config, sources=None, dry_run=False, min_interval=1.5, sleeper=None) -> dict`
  - `sources` default `["admin", "overpass", "ckan"]`; unknown → `VnGeoError`.
  - Plan: admin = one global run (v2); overpass = per area with `overpass` config; ckan = per area's `ckan.datasets`.
  - `dry_run=True` → return `{"dry_run": true, "plan": [...]}` with NO network and NO sleep.
  - Execute (real run): for each step — build the module calls per §2, count changes with the §2 dedup pattern **using each module's `records_to_documents()` output** (url/text), then call the module's `ingest()`. Counts per step: `{"new", "updated", "unchanged"}`.
  - Politeness: `sleeper or time.sleep` between live fetch calls: sleep `min_interval` before every fetch except the first overall.
  - Error isolation: a failing source is recorded as `{"error": "<message>"}` in that step's result and the run CONTINUES; the CLI exits 1 if any error occurred, else 0.
  - After the run: `store.record_event("refresh_run", {"areas": [names], "sources": [...], "totals": {...}})`.
  - Return:
    ```json
    {"dry_run": false,
     "areas": [{"name": "Yên Dũng", "sources": {"admin": {"new": 0, "updated": 0, "unchanged": 3355},
                                                 "overpass": {"new": 0, "updated": 0, "unchanged": 0}}},
                {"name": "Hải Phòng", "sources": {"ckan": {"new": 0, "updated": 0, "unchanged": 1429}}}],
     "totals": {"new": 0, "updated": 0, "unchanged": 4784, "errors": 0}}
    ```
    (admin counts attach to the FIRST area; if no areas, admin still runs and reports under area `"(global)"`.)
- CLI:
  - `python -m vn_geo.refresh coverage --db DB [--config FILE] [--area NAME] [--json]`
  - `python -m vn_geo.refresh run --db DB --config FILE [--sources admin,overpass,ckan] [--dry-run] [--min-interval 1.5] [--json]`
  - Human output: one line per area×source (`admin: new 0 · updated 0 · unchanged 3355`), gaps listed, totals line.
- Fixtures: reuse round-4 fixtures read-only (admin `v2_sample.json`, overpass `yen_dung.json`, enterprises samples) + add `tests/fixtures/vn_geo/refresh/config_areas.json` (valid config with 2 areas). Invalid configs can be built inline in tests.

## §4 `goong.py` (R5-B) — Goong REST client + 1000/day cap

Purpose: call the Goong (VN Google-Maps alternative) REST APIs v2 once the account is activated, with a hard local daily cap of 1000 requests (the free tier) so usage never eats into the $100 balance. **No API key exists yet — write the client + hermetic tests only; no live calls.**

- Constants: `BASE_URL = "https://rsapi.goong.io"` · `DEFAULT_TIMEOUT = 30.0` · `DEFAULT_DAILY_LIMIT = 1000` · `USER_AGENT = "hermes-vn-geo/0.1"` · default key file `<LOCALAPPDATA>/hermes/vn-geo/keys.env` · default usage-state file `<LOCALAPPDATA>/hermes/vn-geo/goong_usage.json` (helper `_default_dir()` → `Path(os.environ.get("LOCALAPPDATA", Path.home() / "AppData/Local")) / "hermes" / "vn-geo"`).
- Key resolution — `resolve_api_key(api_key=None, *, key_file=None) -> str`: explicit arg → env `GOONG_API_KEY` → key file (default above; parse `KEY=value` lines, ignore `#` and blanks, strip quotes) → else `VnGeoError("no Goong API key found: set GOONG_API_KEY or create <path> with GOONG_API_KEY=...")`. NEVER store/log the key; error messages must not include it.
- Daily limiter — `class DailyLimiter(state_path=None, daily_limit=1000)`:
  - state JSON: `{"date": "YYYY-MM-DD", "count": n}`; date rollover resets count.
  - `usage(today=None) -> {"date", "used", "limit", "remaining"}`; `check(today=None)` raises `VnGeoError("Goong daily limit 1000 reached for <date>; retry tomorrow or raise daily_limit")` when `used >= limit`; `record(today=None)` increments + persists. `today` injectable (`YYYY-MM-DD` str) for tests; default = local date.
  - Counting rule: one increment per ATTEMPTED request (record even when the HTTP call fails afterwards).
- `class GoongClient(api_key=None, *, key_file=None, daily_limit=1000, state_path=None, timeout=DEFAULT_TIMEOUT, limiter=None)` — resolves the key in `__init__` (fail fast). Methods (all GET, `api_key` last in the query string, `urllib.parse.urlencode`):
  - `autocomplete(text, *, location=None, limit=5, radius=None, more_compound=None, include_deprecated=False) -> list[dict]` — `/v2/place/autocomplete?input=...` (+`location="lat,lng"` when given, `limit`, `radius`, `more_compound`, `has_deprecated_administrative_unit=true`) → `payload["predictions"]` (list).
  - `geocode(address, *, include_deprecated=False) -> list[dict]` — `/v2/geocode?address=...` → `payload["results"]`.
  - `reverse(latlng, *, limit=None, include_deprecated=False) -> list[dict]` — `/v2/geocode?latlng=lat,lng` (accept `"lat,lng"` str or `(lat, lng)` tuple) → `payload["results"]`.
  - `place_detail(place_id, *, include_deprecated=False) -> dict` — `/v2/place/detail?place_id=...` → `payload["result"]`.
  - `usage() -> dict` — the limiter's usage.
  - Every network method: `limiter.check()` → attempt → `limiter.record()` (in `finally`). `_get(path, params) -> dict` helper: urlopen with `# nosec B310` (§0.8) + timeout; `HTTPError`/`URLError`/timeout → `VnGeoError` (include HTTP status + a short body snippet); JSON parse failure → `VnGeoError`. A non-`"OK"` `status` field in the payload → `VnGeoError("Goong API error: <status> — <message/description if present>")`.
- CLI: `python -m vn_geo.goong <autocomplete|geocode|reverse|detail|usage> ...` — common `[--key-file PATH] [--state-path PATH] [--daily-limit N] [--json]`; e.g. `autocomplete "quán ăn" [--location 21.2,106.25] [--limit 5]`, `geocode "Phường Yên Dũng, Bắc Ninh"`, `reverse 21.2012 106.2493`, `detail PLACE_ID`, `usage`.
